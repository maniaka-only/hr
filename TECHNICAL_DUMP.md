### 2. Архітектура та клієнт-серверна взаємодія

1. **Архітектурна модель:** Повноцінна клієнт-серверна SPA-архітектура. Angular-клієнт взаємодіє з сервером через RESTful JSON API.
2. **HTTP-клієнт (`ApiService` на `Axios`):**
   - Відповідно до вимог, категорично виключено `fetch` та `@angular/common/http` у фронтенді.
   - Створено єдиний екземпляр `axios.create({ baseURL: 'http://localhost:3000/api' })`.
   - **Request Interceptor:** перехоплює всі запити та підставляє `Authorization: Bearer <token>` із `localStorage`.
   - **Response Interceptor:** автоматично очищає токен при отриманні коду `401 Unauthorized`.
3. **Управління реактивним станом (Angular Signals):**
   - Побудовано виключно на Angular Signals (`signal`, `computed`, `effect`).
   - `AuthState`: реактивний стан сесії посадової особи.
   - `PersonnelComponent`: сигнал `filtered = computed(...)` забезпечує синхронний живий пошук за ПІБ, 7-значним індивідуальним номером, посадою, категорією звань та підрозділом.
4. **JWT-аутентифікація:**
   - Stateless-авторизація. Хешування паролів за стандартом bcryptjs (сіль 10 раундів).
   - Публічний доступ до Головної сторінки, Наказів і новин, Галереї, Інформації про сайт, Контактів та структури підрозділів.
   - Закритий доступ (JWT) до повного реєстру особового складу (ПІБ, 7-значні індивідуальні номери, вислуга, сімейний стан, картки) та створення нових підрозділів.

### 3. Реляційна схема бази даних SQLite (`military_hr.db`)

#### Таблиця `users` (Кадровий апарат частини):
- `id` INTEGER PRIMARY KEY AUTOINCREMENT
- `username` TEXT UNIQUE NOT NULL (`admin`)
- `full_name` TEXT NOT NULL (ПІБ посадової особи)
- `role` TEXT DEFAULT 'hr_officer'
- `password_hash` TEXT NOT NULL

#### Таблиця `departments` (Підрозділи військової частини А3114):
- `id` INTEGER PRIMARY KEY AUTOINCREMENT
- `name` TEXT NOT NULL (*Штаб управління*, *1-й механізований батальйон*, *Розвідувальна рота*, *Відділення зв'язку та кібербезпеки*, *Медичний пункт*, *Тилове забезпечення*)
- `code` TEXT NOT NULL (`ШТ-01`, `1-МБ`, `РР-03`, `ЗК-04`, `МП-05`, `ТЗ-06`)
- `commander_name` TEXT NOT NULL
- `commander_rank` TEXT NOT NULL
- `commander_phone` TEXT
- `description` TEXT

#### Таблиця `personnel` (Особовий склад):
- `id` INTEGER PRIMARY KEY AUTOINCREMENT
- `service_number` TEXT UNIQUE NOT NULL — **Індивідуальний номер військовослужбовця (7 цифр, напр. `6284771`, `6284772` тощо)**
- `full_name` TEXT NOT NULL
- `rank` TEXT NOT NULL (*Солдат*, *Старший солдат*, *Сержант*, *Старший лейтенант*, *Капітан*, *Майор*, *Підполковник*)
- `position` TEXT NOT NULL
- `department_id` INTEGER (FK -> `departments(id)` ON DELETE SET NULL)
- `birth_date` TEXT NOT NULL (формат `YYYY-MM-DD`, обчислення повного віку)
- `marital_status` TEXT NOT NULL
- `children_count` INTEGER DEFAULT 0
- `service_years` REAL NOT NULL (вислуга років)
- `enlistment_date` TEXT NOT NULL
- `status` TEXT NOT NULL (*На службі*, *У відрядженні*, *У відпустці*, *На лікуванні*)
- `phone` TEXT
- `notes` TEXT
- `photo_url` TEXT — локальний шлях до фотографії військовослужбовця у формі (`assets/personnel/person1.jpg` .. `person10.jpg`)

#### Таблиця `news` (10 Головних наказів і новин порталу):
- `id` INTEGER PRIMARY KEY AUTOINCREMENT
- `title` TEXT NOT NULL
- `date` TEXT NOT NULL
- `category` TEXT NOT NULL (*Кадри*, *Бойова підготовка*, *Озброєння*, *Офіційно*, *Медицина*, *Події*, *Спорт*, *Аналітика*)
- `summary` TEXT NOT NULL
- `content` TEXT NOT NULL — повний текст наказу або публікації з точними ПІБ, індивідуальними номерами, підписами та пунктами наказів
- `image_url` TEXT

### 4. Специфікація розробленого REST API

| Метод | URL | Рівень доступу | Вхідні дані | Тіло відповіді | Опис |
|---|---|---|---|---|---|
| `POST` | `/api/auth/login` | Публічний | `{ username, password }` | `{ token, user }` | Авторизація кадровика, перевірка bcrypt, видача JWT |
| `GET` | `/api/auth/me` | JWT Bearer | — | `{ user }` | Отримання профілю поточного кадровика |
| `GET` | `/api/news` | Публічний | `?limit=10` | Масив 10 новин | Вивід 10 головних наказів та новин частини |
| `GET` | `/api/news/:id` | Публічний | `id` у URL | Об'єкт новини | Повний текст наказу або прес-релізу |
| `GET` | `/api/gallery` | Публічний | — | Масив світлин | Список фотографій з категоріями |
| `GET` | `/api/departments` | Публічний | — | Масив підрозділів | Підрозділи з кількістю бійців (`personnel_count`) |
| `POST` | `/api/departments` | JWT Bearer | Дані відділу | Створений відділ | Додавання нового штатного підрозділу |
| `PUT` | `/api/departments/:id` | JWT Bearer | Оновлені поля | Збережений відділ | Редагування відділу та призначення командира |
| `GET` | `/api/stats` | Публічний | — | Статистика | Загальна статистика укомплектованості частини |
| `GET` | `/api/personnel` | JWT Bearer | — | Реєстр особового складу | Повний список бійців з 7-значними номерами та фото |
| `GET` | `/api/personnel/:id` | JWT Bearer | `id` у URL | Картка бійця | Повна особова справа для перегляду та друку |
| `POST` | `/api/personnel` | JWT Bearer | Поля картки бійця | Створена картка | Зарахування бійця до списків особового складу |
| `PUT` | `/api/personnel/:id` | JWT Bearer | Оновлені дані | Оновлена картка | Оновлення звання, посади, статусу, вислуги років |
| `DELETE`| `/api/personnel/:id` | JWT Bearer | `id` у URL | 204 No Content | Зняття військовослужбовця з обліку |
| `GET` | `/api/health` | Публічний | — | `{ status: 'ok' }` | Перевірка працездатності сервера |
